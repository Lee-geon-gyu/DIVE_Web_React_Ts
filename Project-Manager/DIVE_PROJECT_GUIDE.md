UI/UX 디자인과 웹 퍼블리싱을 처음 공부하는 사용자를 위한 정보형 웹사이트를 제작해줘.

프로젝트는 단순한 링크 모음이 아니라, 초심자가 필요한 정보를 목적에 따라 쉽게 탐색하고 학습할 수 있는 웹 서비스 형태로 구현한다.

## 1. 프로젝트 개요

프로젝트명은 임시로 `DIVE`를 사용한다.

DIVE는 UI/UX 디자인과 웹 퍼블리싱을 처음 시작하는 사용자가 디자인 레퍼런스, AI 도구, 디자인 리소스, 반응형 웹, 웹 라이브러리 등의 정보를 한곳에서 탐색할 수 있도록 도와주는 정보 큐레이션 플랫폼이다.

주요 사용자는 다음과 같다.

- UI/UX 디자인을 처음 공부하는 사용자
- 웹디자인과 퍼블리싱을 함께 공부하는 사용자
- 실무에 필요한 디자인 리소스를 찾는 사용자
- 반응형 웹과 인터랙션 라이브러리를 공부하는 사용자
- 다양한 AI 도구의 특징과 활용 방법을 비교하고 싶은 사용자

## 2. 전체 디자인 방향

전체적인 디자인은 Toss의 친근하고 직관적인 UI와 ChatGPT의 차분하고 정돈된 인터페이스를 결합한 느낌으로 제작한다.

단, Toss나 ChatGPT의 화면을 그대로 복제하지 말고 다음 특징만 참고한다.

### Toss에서 참고할 요소

- 큰 제목과 명확한 정보 위계
- 둥근 카드와 버튼
- 넉넉한 여백
- 친근하고 부드러운 인터랙션
- 복잡한 정보를 쉽게 이해할 수 있도록 구성한 레이아웃
- 중요한 콘텐츠를 강조하는 대형 카드

### ChatGPT에서 참고할 요소

- 차분하고 절제된 색상
- 집중하기 쉬운 콘텐츠 구조
- 간결한 사이드바 또는 카테고리 탐색 구조
- 콘텐츠 중심의 정돈된 레이아웃
- 부드러운 회색 계열 배경
- 사용자가 현재 보고 있는 위치를 쉽게 이해할 수 있는 UI

전체적으로 깔끔하고 현대적이며, 학습 플랫폼처럼 신뢰감이 느껴져야 한다.

과도하게 화려하거나 장식적인 디자인은 피하고, 정보 탐색과 가독성을 가장 중요하게 구성한다.

## 3. 컬러와 스타일

기본 배경은 완전한 흰색보다 아주 옅은 회색이나 아이보리 계열을 사용한다.

추천 컬러 방향은 다음과 같다.

- 메인 배경: `#F7F8FA`
- 카드 배경: `#FFFFFF`
- 주요 텍스트: `#191F28`
- 보조 텍스트: `#6B7684`
- 테두리: `#E5E8EB`
- 포인트 컬러: 부드러운 블루 또는 블루 퍼플
- 성공 또는 무료 표시: 차분한 그린
- 경고 또는 유료 표시: 부드러운 오렌지

색상은 CSS 변수로 관리한다.

카드는 16px에서 24px 정도의 둥근 모서리를 사용하고, 그림자는 매우 은은하게 적용한다.

버튼과 입력창도 둥근 형태로 통일한다.

## 4. 폰트와 타이포그래피

한글 가독성이 좋은 Pretendard 또는 시스템 폰트를 사용한다.

제목은 굵고 명확하게, 본문은 편안하게 읽히도록 구성한다.

타이포그래피 예시는 다음과 같다.

- 메인 타이틀: 48px 이상
- 섹션 타이틀: 28px에서 36px
- 카드 타이틀: 18px에서 22px
- 본문: 15px에서 17px
- 보조 설명: 13px에서 15px

반응형 환경에서는 `clamp()`를 사용해 글자 크기가 자연스럽게 변하도록 한다.

## 7. 공통 기능

다음 기능을 구현한다.

### 검색

- 사이트 전체 통합 검색
- 제목, 설명, 태그를 기준으로 검색
- 입력과 동시에 결과가 표시되는 실시간 검색
- 검색 결과가 없을 때 안내 화면 표시
- 최근 검색어를 localStorage에 저장
- 최근 검색어 삭제 기능

### 필터와 정렬

- 다중 필터
- 필터 초기화
- 선택된 필터를 칩 형태로 표시
- 인기순, 최신순, 이름순 정렬
- 모바일에서는 필터를 바텀시트 또는 드로어 형태로 표시

### 즐겨찾기

- 로그인 없이 localStorage를 사용
- 카드에서 바로 즐겨찾기 가능
- 즐겨찾기 전용 페이지 구현
- 즐겨찾기가 없을 때 빈 상태 화면 표시

### 비교

- AI 도구와 웹 라이브러리를 최대 3개까지 비교
- 하단 고정 비교 바 표시
- 비교 대상 삭제 기능
- 비교 페이지에서 표 형태로 차이점 표시

### 다크 모드

- 라이트 모드와 다크 모드 지원
- 사용자의 시스템 설정을 초기값으로 사용
- 사용자가 선택한 모드를 localStorage에 저장
- 다크 모드에서도 충분한 명도 대비 유지

### 반응형

다음 환경을 고려한다.

- 데스크톱: 1440px 이상
- 노트북: 1024px에서 1439px
- 태블릿: 768px에서 1023px
- 모바일: 767px 이하

모바일에서는 카드가 1열로 배치되고, 내비게이션은 햄버거 메뉴 또는 하단 내비게이션으로 변경한다.

## 9. 인터랙션

인터랙션은 화려함보다 자연스러움과 사용성을 우선한다.

- 페이지 진입 시 콘텐츠 fade-up
- 검색창 focus 효과

## 12. 데이터 구조

각 콘텐츠 데이터는 일관된 객체 구조로 작성한다.

예시:

```ts
interface ResourceItem {
  id: string;
  title: string;
  description: string;
  category: string;
  tags: string[];
  image: string;
  url: string;
  isFree: boolean;
  isBeginnerFriendly: boolean;
  supportsKorean: boolean;
  difficulty: "beginner" | "intermediate" | "advanced";
  pricing?: string;
  license?: string;
  commercialUse?: boolean;
  attributionRequired?: boolean;
  features?: string[];
  pros?: string[];
  cons?: string[];
}
```

UI/UX, AI 도구, 디자인 리소스, 웹 라이브러리는 각각 별도의 JSON 또는 TypeScript 데이터 파일로 관리한다.

초기 샘플 데이터는 카테고리별로 최소 8개 이상 작성한다.

실제 외부 서비스의 가격이나 라이선스 정보는 변경될 수 있으므로, 화면에 “정보는 공식 사이트에서 다시 확인해주세요”라는 안내를 표시한다.

## 13. 코드 작성 조건

- 모든 코드는 실제 실행 가능한 형태로 작성
- 임시 주석만 남기고 기능을 생략하지 않기
- 반복되는 코드는 컴포넌트 또는 함수로 분리
- 명확한 변수명과 함수명 사용
- 콘솔 오류가 발생하지 않도록 작성
- 모바일과 데스크톱 모두 확인
- 이미지가 없을 경우 깨진 이미지 대신 placeholder 표시
- 외부 링크에는 `target="_blank"`와 `rel="noopener noreferrer"` 적용
- 불필요한 라이브러리는 사용하지 않기
- CSS에 과도한 `!important` 사용 금지
- 레이아웃을 고정 px 값에만 의존하지 않기
- CSS 변수와 공통 스타일 적극 활용
- 컴포넌트별 역할을 명확히 분리

### Project Decisions

1. MVP 범위

- Home
- Header
- Footer
- 검색
- 카테고리 탐색
- 리소스 리스트

다음 기능은 MVP에서 제외하고 추후 확장으로 분류한다.

- 로그인

- 댓글
- 평점

2. 상세 화면 방식

상세 콘텐츠는 Modal이 아니라 React Router 기반의 독립 Route(Page)로 구현한다.

예시

/reference/figma
/reference/gsap
/ai/chatgpt

3. 모바일 Navigation

모바일에서는 Header 우측 햄버거 버튼을 사용한다.

햄버거 버튼을 누르면 오른쪽에서 Drawer(Menu)가 나타난다.

1차 메뉴는 Accordion 형태로 열리고 닫힌다.

2차 메뉴는 필요한 메뉴에만 구현한다.

4. 배경색 및 Breakpoint

기본 배경은 White 기반으로 사용한다.

필요한 섹션만 Gray50을 사용한다.

Breakpoint는 다음을 유지한다.

- Mobile: 0~767px
- Tablet: 768~1279px
- Desktop: 1280px 이상

320px과 375px 환경을 반드시 지원한다.

이 네 가지를 프로젝트 기준으로 확정한다.

이제 문서 분석 단계는 종료하고 개발을 시작해도 된다.

다음 단계는

1. 프로젝트 기반 설정
2. 디자인 토큰 및 Reset
3. 공통 Layout
4. Header
5. Footer

순서로 진행한다.

한 단계씩 구현하고 완료 후 다음 단계로 넘어간다.

한 번에 전체 프로젝트를 구현하지 않는다.
